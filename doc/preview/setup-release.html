New Cloudflare account preparation.

Persiapan sebelum melakukan remote work pada akun Cloudflare baru.

1. Authenticate

Otentikasi Wrangler ke akun Cloudflare yang dituju melalui metode yang disetujui operator.

2. Confirm identity

Gunakan npx wrangler whoami untuk memastikan identitas akun tanpa mencetak token rahasia.

3. Unique resources

Tentukan tenant slug, Worker name, domain, D1 name, KV name, dan R2 bucket name yang unik secara global.

4. Decide ingress

Putuskan penggunaan custom-domain versus service-only sebelum melakukan provisioning.

5. Review registry

Tinjau environment mana yang benar-benar milik akun Cloudflare tersebut. Jangan menggunakan resource ID milik akun lain.

Install dan Provisioning Toolchain.

Installer repository menangani provisioning environment secara otomatis. Tidak perlu global Astro, TypeScript, atau Wrangler.

# Dari repository root
./scripts/install.sh

# Pastikan registry dapat dibaca
npm run tenant:list
npm run tenant:validate
Expected CMSAds tenant slug: hanya petanisejahtera-preview. Production Petani Sejahtera sengaja berada di luar registry CMSAds.

Siapkan satu tenant lokal.

Local migration dan dev server wajib menyebut tenant. Resource remote tidak disentuh.

Siapkan development variables

Buat .dev.vars.<tenant> melalui jalur aman. Jangan print, paste ke chat, commit, atau salin secret tenant lain.

Apply local D1 migration

npm run tenant:migrate:local -- petanisejahtera-preview

Jalankan selected tenant

npm run tenant:dev -- petanisejahtera-preview

Deploy exact tenant dan exact layer.

Storefront deploy, CMSAds deploy, dan remote D1 migration adalah tiga operasi terpisah. Satu approval tidak mengizinkan dua operasi lain.

CMSADS APPROVAL

Publish backend Worker

CF_DEPLOY_REMOTE=1 \
npm run tenant:deploy -- <tenant>

Wrapper revalidates bindings, ingress mode, route shape, build, dry-run, dan generated config. Service-only deploy tidak memiliki public target.

SEPARATE APPROVAL

Remote D1 migration

CF_D1_REMOTE=1 \
npm run tenant:migrate:remote -- <tenant>

Deploy approval tidak mengizinkan migration. Migration approval tidak mengizinkan deploy.

Frontend release: jalankan build, test, dan deploy dari repository storefront tenant. Deploy CMSAds tidak mengirim bundle public tersebut.
Jangan gunakan: direct wrangler deploy, unnamed migration, loop semua tenant, atau memindahkan domain untuk memperbaiki backend.

Verifikasi deployed artifact.

Catat repository layer, tenant, Worker name, ingress, route atau service binding, Version ID, dan non-actions.

Storefront surface

Home dan satu known product route mengembalikan UI tenant yang benar pada mobile dan desktop.

Gateway route

Pada headless tenant, /hello harus mencapai CMSAds dan URL browser tetap memakai origin storefront.

Auth boundary

Unauthenticated /admin/* masuk ke login. Protected admin API memberi JSON 401.

Ingress proof

Service-only backend melaporkan tidak ada public target. Custom-domain tenant mempertahankan exact hostname yang direview.

Affected browser flow

Uji viewport relevan, console, failed request, focus, interaction state, horizontal overflow, dan API response yang dipakai frontend.

Record evidence

Update STATUS, BUILD-LOG, task state, commit, Worker, Version ID, check yang tidak dilakukan, dan unrelated files yang ditinggalkan.

Selection-only QA: jangan klik provider, payment, pickup, messaging, content publish, atau order mutation tanpa approval side effect yang spesifik.

Secrets dan configuration boundary.

Local only

.dev.vars.<tenant> tidak dibaca, dicetak, atau di-commit tanpa explicit need dan approval.

Tenant D1

Masked Mengantar dan AutoLaris configuration dapat diganti dari authenticated Profile. Empty key mempertahankan value aktif.

Cloudflare secret

Webhook secret tetap server-managed dan tidak tersedia untuk replacement melalui admin browser.

Public vars

Nama, logo, canonical origin, locale, template, dan theme boleh berada di typed Worker vars.
