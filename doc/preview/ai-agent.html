Kunci repository layer, tenant, dan boundary sebelum edit.

Nyatakan outcome

Definisikan behavior atau artefak yang harus berubah. Jangan menambahkan retries, abstraction, telemetry, atau dependency yang tidak diminta.

Pilih owner repository

Public layout dan static assets milik storefront tenant. Admin, API, order, shipping, payment, dan tracking backend milik CMSAds. Jangan mengubah layer lain untuk menyelesaikan symptom.

Pilih exact tenant

Gunakan npm run tenant:list. Jangan infer dari branch, Worker, hostname, percakapan lama, atau deployment sebelumnya.

Temukan source dan caller

Baca owning specification, source section lengkap, shared helper, schema, route, dan seluruh caller, termasuk adapter frontend lintas repository, sebelum mengubah exported API contract.

Pisahkan unrelated work

Perubahan operator di working tree tidak boleh ditimpa, di-stage, dibersihkan, atau ikut deploy.

Bug fix

Reproduce request/flow sebelum patch, lalu ulangi scenario yang sama.

UI change

Buka selected tenant di browser nyata; cek desktop/mobile, keyboard, state, console, network, overflow.

API/feature

Jalankan contract test yang melindungi behavior baru dan smoke route nyata.

Docs only

Audit link, fragment, ID, nav, portable path, source ownership, dan diff whitespace.

Gunakan proof yang tepat.

Build hijau bukan browser proof. Local stub bukan live-provider proof. Dry-run bukan deployment.

Shell permission bukan operator approval.

SECRETS

Jangan baca, print, copy, atau simpan API key, password, token, auth session, payment data, atau customer data tanpa exact need dan approval.

REMOTE

Deploy, D1 remote write/migration, DNS/domain, secret, KV, R2, content publish, dan Worker mutation membutuhkan approval terpisah.

PROVIDER

Mengantar order/pickup, payment test, messaging, dan live order mutation harus menyebut side effect dan tenant.

GIT

Commit dan push hanya jika diminta. Stage hanya file scope; push ke auto-deploy branch tetap production gate.

Release memakai wrapper repository dan exact layer.

Storefront Worker, CMSAds Worker, dan D1 migration memiliki command, artifact, dan approval yang berbeda.

Remote migration

CF_D1_REMOTE=1 \
npm run tenant:migrate:remote -- <tenant>

Approval migration tidak mengizinkan deploy.

Worker deploy

CF_DEPLOY_REMOTE=1 \
npm run tenant:deploy -- <tenant>

service-only backend harus tetap tanpa public target. Approval deploy tidak mengizinkan migration, storefront deploy, atau tenant lain.

Headless tenant: perubahan visual public harus dikerjakan dan dirilis dari repository storefront. Breaking CMSAds API tetap wajib memigrasikan dan menguji adapter storefront walaupun bundle visual tidak berubah.
Dilarang: direct wrangler deploy, unnamed migration, loop seluruh tenant, suffix environment kedua, atau retry production ketika preview gagal.

Worker cleanup tidak boleh menyentuh storage secara implisit.

Bandingkan registry dan account inventory

Mulai dari tenant:list --json, lalu cek exact Worker yang tampak duplikat.

Buktikan tidak terpakai

Periksa Custom Domain, zone route, enabled workers.dev, current deployment, dan bindings.

Minta approval exact name

Approval harus menyebut satu Worker. Jangan memakai --force tanpa dependency review terpisah.

Delete Worker saja

D1, KV, R2, DNS, domain, secrets, dan sibling Worker tetap ada kecuali masing-masing mendapat approval.

Verifikasi ulang

Re-list Worker/domain dan smoke canonical hostname. Laporkan resource yang dipertahankan.

Current evidence: registry hanya memuat satu preview tenant. Named resources yang telah dihapus tidak boleh dipakai sebagai bukti keberadaan Worker atau storage.

Handoff berisi evidence dan non-actions.

Wajib dilaporkan

  • • Files dan contract yang berubah.
  • • Exact command/browser/request yang dijalankan.
  • • Observed result dan limitation.
  • • Tenant, Worker, domain, version, migration, dan deployment state.
  • • Provider/remote/data action yang sengaja tidak dilakukan.
  • • Commit, branch, push, dan working-tree state.

Tidak boleh diklaim

  • • “Works” tanpa executable proof.
  • • Live-provider success dari stub atau credential-missing response.
  • • Deployment dari build atau dry-run.
  • • Complete ketika masih ada placeholder, stale spec, atau unverified caller.
  • • Clean tree tanpa memeriksa scoped status setelah commit.
