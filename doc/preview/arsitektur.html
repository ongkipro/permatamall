Stack runtime.

Presentation public boleh memakai stack apa pun. CMSAds tetap memakai Astro dan React untuk API, admin, dan operational workflow.

Storefront presentation

Astro, Shopify, WordPress, React, static HTML, atau framework tenant lain. Tenant menguasai layout, catalog presentation, funnel, dan checkout UI.

Gateway dan application

Storefront Worker melayani public assets dan meneruskan route CMSAds. Backend menangani schema validation, order persistence, session, provider resolver, tracking guards, dan tenant contract.

State

Cloudflare D1 sebagai commerce source of truth. R2 untuk tenant media. KV untuk session dan quota. Secret storage untuk credential server.

Edge runtime

Storefront Worker memiliki domain public. CMSAds dapat memakai service-only tanpa public route atau custom-domain untuk deployment terpadu.

Providers

Mengantar untuk location, rates, receiver history, shipment creation, dan pickup. AutoLaris untuk payment. Meta dan Google untuk measurement.

Frontend integration contract.

Desain bebas tidak berarti business rules bebas. Frontend harus menjadi caller tipis dan tidak mengambil alih authority backend.

Ads dan attribution

Muat Meta Pixel, GTM, atau Google identifiers dari config tenant. Pertahankan event_id, _fbp, _fbc, gclid, gbraid, dan wbraid sampai submit order.

Location

Gunakan /api/locations untuk autocomplete kecamatan. Simpan identity hasil selection, bukan label atau area ID hasil tebakan browser.

Shipping quote

Kirim product atau variant, quantity, dan destination. CMSAds mengambil weight dan eligible service dari canonical state lalu mengembalikan rate.

Submit order

/api/submit-order memvalidasi ulang product, variant, stock, price, destination, courier, ongkir, payment, dan attribution sebelum menulis D1.

Confirmation

Render invoice, payment instruction, dan outcome dari response backend. Frontend tidak membuat status sukses, resi, atau provider identity sendiri.

Compatibility

API field, status, error shape, product ID, dan variant ID adalah contract lintas repository. Breaking change harus mengubah dan menguji seluruh adapter tenant.

Logical data model.

Schema ini dibuat ulang di setiap D1 tenant. Garis menunjukkan ownership atau reference utama.

stores

identity, ads config, provider config, content instruction

warehouses

origin area, pickup address, PIC

courier_rules

service dan COD availability

products → product_variants

slug, active state, SKU, price, stock, weight

orders → order_items

invoice, customer, payment status, shipping status, provider identity, cnote

payment_transactions

provider reference, amount, fee, instruction, expiry, status

storefront_content

home atau product key, draft, published JSON

pickup_schedules

warehouse, schedule, local atau provider state

receiver snapshots

per-courier totals, delivered, RTS, delivery rate

Catalog identity

D1 integer ID adalah identity untuk catalog dan ads content_id.

Order identity

Invoice INV-YYYYMMDD-XXXXXXXX dipakai operator. D1 primary key dipakai internal.

Provider identity

Hanya ditulis setelah provider menerima request. Bukan pengganti canonical order ID.

AI content lifecycle.

Workers AI tidak memiliki jalur langsung untuk mengubah storefront. Standalone frontend juga tidak berubah sampai adapter-nya membaca published content.

Operator menyimpan instruction tenant

Instruction non-secret disimpan di D1 Worker aktif dan tidak ditanam ke repository.

Worker memuat facts operasional

Homepage menerima catalog product dan variant aktif; product detail menerima ID, title, slug, image, price, stock, dan weight dari D1. AI tidak dapat menulis harga, stock, provider, ads credential, atau order state.

Workers AI menghasilkan candidate JSON

Response melewati size check dan strict structured schema. Raw HTML, filename/route rekaan, rating, sales count, dan testimonial AI ditolak atau diwajibkan kosong.

Draft disimpan tanpa publication

Generation failure atau invalid output tidak mengubah content public yang sedang tayang.

Operator review dan publish

Explicit publish menyalin draft yang valid ke published JSON. Storefront hanya membaca published record.

Headless boundary: publish mengubah canonical content di D1. Storefront CMSAds dapat membacanya langsung; storefront standalone perlu public content adapter sebelum perubahan tersebut terlihat.
